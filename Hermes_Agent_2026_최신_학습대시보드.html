2. 핵심 구성요소 8개

🧠 Memory

세션을 넘어 사용자 선호, 프로젝트 정보, 경험을 유지합니다.

🧩 Skills

반복 업무를 재사용 가능한 “작업 설명서”로 축적합니다.

🛠 Tools

브라우저, 파일, 터미널, 검색 등 실제 기능을 실행합니다.

👥 Subagents

복잡한 업무를 여러 하위 AI에 분담·병렬 처리합니다.

🤖 Bot Mode

각기 다른 역할·기억·도구를 가진 전문 Bot을 팀처럼 운영합니다.

⏰ Cron

반복 업무를 예약하고, 최신 버전에서는 작업 연속성과 메모리도 강화했습니다.

🔌 MCP

AI와 외부 도구·서비스를 표준 방식으로 연결합니다.

🔄 A2A

Agent와 Agent가 서로 업무를 주고받는 상호운용 구조입니다.

Memory를 쉽게 이해하기

Memory는 “지난 대화를 통째로 외우는 것”만을 뜻하지 않습니다. 사용자 선호, 환경 정보, 프로젝트 맥락, 반복해서 쓰는 사실을 다음 세션에서 활용할 수 있게 유지하는 구조입니다.

주의: API Key, 비밀번호, 개인정보 같은 민감정보는 일반 Memory보다 별도의 Secret 관리 정책이 필요합니다.

Skill과 Tool의 차이

Skill = 일을 하는 방법, Tool = 실제로 실행하는 기능입니다. “공식자료 우선으로 AI 최신 뉴스 조사하기”는 Skill이고, 웹 검색 기능은 Tool입니다.

Subagent와 Bot Mode

Subagent는 특정 업무를 잠시 나눠 맡는 작업자에 가깝습니다. Bot Mode의 Bot은 역할·모델·지침·기억·Skill·Tool·대화 기록을 독립적으로 갖는 장기 전문 구성원에 가깝습니다.

Cron + Memory

“매주 금요일 조사”처럼 예약 실행할 수 있고, 2026년 8월 이후에는 작업별 메모리·연속성이 강화되어 지난 실행 결과를 다음 실행과 연결하는 구조가 중요해졌습니다.

4. 보안 — 가장 중요한 부분

Hermes는 실제 파일·터미널·브라우저를 다룰 수 있습니다. 따라서 일반 챗봇보다 권한이 강하고, 승인·Secret 관리·Skill/MCP 검증이 중요합니다.
☑ 위험 명령 승인 유지
☑ API Key를 일반 대화에 노출하지 않기
☑ 외부 Skill 설치 전 검사
☑ MCP 서버 권한 확인
☑ 삭제·게시·결제는 사람 최종 승인
☑ 업데이트 전 세션/DB 백업
☑ Agent 지침 파일 쓰기 승인
☑ 승인 우회 모드는 테스트 환경 중심

5. 장점과 단점

장점 ① 오픈소스

MIT License. 코드 감사·수정·확장 가능.

장점 ② Provider 독립성

여러 LLM Provider와 사용자 지정 Endpoint를 선택 가능.

장점 ③ 기억과 학습

Memory + Skill로 개인화된 장기 작업 환경 구성.

장점 ④ 자동화와 협업

Cron + MCP + Browser + Subagent + Bot Mode.

주의 ① 복잡도

초보자에게 Provider, 권한, Tool, MCP 설정이 복잡할 수 있음.

주의 ② 강한 권한

컴퓨터를 직접 다룰 수 있어 잘못된 실행의 영향이 큼.

주의 ③ 빠른 업데이트

짧은 기간에 대규모 변경이 들어가므로 버전별 차이 큼.

주의 ④ 운영 안정성

v0.21.2의 DB 패치처럼 큰 업데이트 후 충분한 검증 필요.
